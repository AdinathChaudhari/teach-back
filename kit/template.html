1

What snip does

Bet first

Someone pastes a very long link into snip. In one line: what do they get back, and what happens when a friend opens it?

They get a short link with a six-character code. When a friend opens it, snip looks the code up and sends the browser on to the long URL src/snip/store.py:37.

That is the whole product. A redirect (a reply that says "the page you want lives at this other address") does the last step. The rest of snip exists to make the code and to remember it.

Make a code, remember it, look it up.

Open question: snip must remember a code between two visits. Where does it keep it, and what stops two links from sharing one code? Section 2 answers.

One short link, four steps

Bet first
When snip saves a new link and the random code already exists, what does it do?

It picks a new random code, again and again, until the code is free src/snip/store.py:44. Only then does it store the long URL under that code src/snip/store.py:46.

Press Next to walk one save, one box at a time. Each box matches one step in the list below it.

  1. Step 1, RECEIVE: the long URL arrives. The caller passes one long URL to save src/snip/store.py:40
  2. Step 2, READ: load the table. The whole table is read from one file. A missing file counts as an empty table src/snip/store.py:42 src/snip/store.py:18
  3. Step 3, CODE: pick a free code. A code has 6 characters from lowercase letters and digits. If it is taken, snip picks again src/snip/store.py:12 src/snip/store.py:44
  4. Step 4, WRITE: save the table. The long URL goes in under the code, and the whole table is written back src/snip/store.py:46 src/snip/store.py:47
Why?

snip writes the whole table back on every save. Work out one cost of that choice and one thing it keeps simple.

The cost: every save rewrites the whole file, so it slows down as the table grows src/snip/store.py:26. The gain: there is one file and no database to run. The code comment says it assumes one writer at a time src/snip/store.py:25.
